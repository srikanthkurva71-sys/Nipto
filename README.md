# Nipto Social

**Nipto is an Android-first social communication app built around one Nipto ID.** It brings private messaging, status updates, social discovery, profiles and short-form video into one simple, fast experience.

This repository is the first implementation of Nipto Social. The former ride-hailing direction is out of scope.

## Product principles

- **One identity:** people register with a unique Nipto ID and sign in with that ID and their password.
- **Private by default where it matters:** private accounts, message membership checks, blocked-user enforcement and private media buckets.
- **Fast and calm:** four primary destinations, lightweight chat lists, paginated feeds and lazy video playback.
- **Creator-friendly:** simple status and short-video publishing, with content moderation before public distribution.
- **Android first:** Flutter + Dart. No web product is planned for v1.

## Main navigation

1. **Home** — paginated feed of approved posts, likes and comments from accounts visible to the signed-in user.
2. **Chats** — inbox, Nipto ID search, discovery, following, direct/group chats, 24-hour statuses and activity notifications.
3. **Shorts** — a vertical, swipe-first short-video feed with likes, comments and creator profiles.
4. **You** — personal profile, followers/following, photo posts, settings, privacy and security.

## Local Android setup

Install Flutter stable, Java 17 and the Android SDK. From the repository root:

~~~powershell
.\\scripts\\bootstrap_nipto_windows.ps1
cd mobile/app
flutter run
~~~

The Flutter app includes the Nipto Supabase project URL and publishable key as client-safe defaults, so ordinary `flutter run`, `flutter run -d chrome`, and `flutter build apk` commands work without a configuration file. The Chrome host is for development preview only; Android remains the sole product target. Optional `--dart-define` values can override these defaults for another environment. A publishable key is intended for client apps; never embed a service-role key or backend secret.

The manifest setup script adds the `nipto://auth-callback` deep link required for Supabase OAuth. The Supabase Auth URL configuration must also allow that redirect URL.

## Run from VS Code

Open the repository root in VS Code, install the Flutter and Dart extensions, connect an Android phone or emulator, then select **Nipto (Android)** in Run and Debug and press F5. The launch configurations point to `mobile/app` and require no separate Supabase config file.

Nipto v1 is an Android app, not a web product. Use an Android emulator or physical Android device for plugin, media and calling validation.

## Supabase state

The connected Supabase project has the social schema and the Nipto native-auth database migrations applied. The live Edge Function inventory currently contains only `nipto-login`; `nipto-identity` has not yet been deployed. Supabase Auth does not yet have the `custom:nipto` OIDC provider enabled, which is why the Flutter OAuth request currently returns `Unsupported provider: custom provider custom:nipto not found`.

**Authentication status:** The Flutter app and repository contain the Nipto ID/password flow and the OIDC issuer implementation. The intended identity model is Nipto ID + password only, with no email or phone required. A recovery Nipto account is optional and is linked only after sign-in in Settings, with approval from the other account owner. The remaining activation steps are server-secret configuration, issuer deployment, and registering the `custom:nipto` provider in Supabase Auth. See `docs/NIPTO_NATIVE_AUTH_DESIGN.md` and `docs/NIPTO_OIDC_DEPLOYMENT.md`. Do not present Nipto sign-in as operational until a real end-to-end login succeeds.

## Current implementation status

The repository contains a Flutter Android app and a Supabase-backed social schema. Implemented app areas include profile editing and avatar uploads, photo posts, Nipto ID discovery and follow requests, direct/group conversations, text messages and basic media attachments, 24-hour statuses with viewer lists and Close Friends controls, Shorts upload/feed interactions, Home feed, in-app notifications, privacy controls, blocking/reporting, and private feedback intake/history. The Nipto identity branch now contains the Nipto ID/password UI, encrypted session manager, ES256 JWT issuer/JWKS, existing-session migration bridge, optional recovery Nipto account flow, one-time password reset grants, device-session management, and self-hosted TURN credential issuance. These new authentication and calling components are not yet production-validated or deployed. Other app areas still require deeper end-to-end, device, moderation, and performance validation.

The feedback subsystem is separate from abuse reports. Signed-in users can submit app-experience ratings, bug reports, feature ideas or support requests and view their own submission status. Feedback is protected by RLS and limited to five submissions per account per 24 hours. A trusted staff-role backend, moderation queues, audit logging and user response notifications are implemented. A role-gated staff console for feedback, reports and content review is implemented, including private signed media previews. Formatting, static analysis, unit/widget tests and Android debug APK CI have passed. Production staff-session acceptance testing remains an operational gate.

All public application tables currently have Row Level Security enabled. Anonymous table privileges were revoked and client writes were narrowed. Authenticated application and moderation SECURITY DEFINER RPCs are explicitly granted to signed-in users and validate access server-side; private policy helpers and staff tables are not client-readable. The Supabase advisor continues to report these authenticated RPCs for manual review.

GitHub Actions generates the Android platform project, then runs Dart formatting, static analysis, tests and an Android debug APK build. The resulting `nipto-android-debug` APK is available as a workflow artifact. A passing CI run proves that the checked commit builds; it does not prove complete device-level or production readiness.
