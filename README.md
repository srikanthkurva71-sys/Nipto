# Nipto Social

**Nipto is an Android-first social communication app built around one Nipto ID.** It brings private messaging, status updates, social discovery, profiles and short-form video into one simple, fast experience.

This repository is the first implementation of Nipto Social. The former ride-hailing direction is out of scope.

## Product principles

- **One identity:** people register with a unique Nipto ID and sign in with that ID and their password.
- **Private by default where it matters:** private accounts, message membership checks, blocked-user enforcement and private media buckets.
- **Fast and calm:** four primary destinations, lightweight chat lists, paginated feeds and lazy video playback.
- **Creator-friendly:** simple status and short-video publishing, with content moderation before public distribution.
- **Android first:** Flutter + Dart. No web product is planned for v1.

## Main navigation

1. **Home** — paginated feed of approved posts, likes and comments from accounts visible to the signed-in user.
2. **Chats** — inbox, Nipto ID search, discovery, following, direct/group chats, 24-hour statuses and activity notifications.
3. **Shorts** — a vertical, swipe-first short-video feed with likes, comments and creator profiles.
4. **You** — personal profile, followers/following, photo posts, settings, privacy and security.

## Local Android setup

Install the Flutter stable SDK and Android SDK, then generate the Android platform folder if it is not present:

~~~bash
flutter create --platforms=android --org com.nipto --project-name nipto .
flutter pub get
flutter analyze
flutter test
~~~

The repository includes `config/dev.json` with the Nipto project URL and its client-safe publishable key. This is a public client key, not a secret; Supabase Row Level Security remains mandatory. Do not put service-role or secret keys in this file.

Run locally using the checked-in config:

~~~bash
flutter run --dart-define-from-file=config/dev.json
~~~

Build a release APK using the same config:

~~~bash
flutter build apk --release --dart-define-from-file=config/dev.json
~~~

In VS Code, select **Nipto (Android)** in Run and Debug and press F5. The launch configuration loads `config/dev.json` automatically. For a local checkout, fetch the latest repository changes once with `git pull origin main`; after that, normal VS Code runs do not require opening GitHub in a browser.

The publishable key is intended for client applications; RLS is the security boundary. Secret/service-role keys are backend-only.

## Run from VS Code

Open this repository folder in VS Code, install the Flutter and Dart extensions, connect an Android phone with USB debugging enabled (or start an Android emulator), and select that Android device in the VS Code device picker. Open Run and Debug and choose **Nipto (Android)**, then press F5. The checked-in `.vscode/launch.json` supplies the Supabase project URL and its client-safe publishable key through Dart defines.

Nipto v1 is an Android app, not a web product. A browser preview at a `localhost` address is not the supported release target; use an Android emulator or physical Android device for feature and plugin testing. Never replace the publishable key with a Supabase secret or service-role key.

## Supabase state

The initial social schema and security migrations are applied to the connected Nipto Supabase project. See supabase/migrations/. The nipto-login Edge Function is deployed with JWT verification disabled because it is the unauthenticated sign-in endpoint; it has its own input validation and database-backed attempt limiting.

New users register with a recovery email, a Nipto ID and a password. Supabase Auth verifies and stores credentials. The profile trigger stores only the public Nipto ID and display name. Login resolves the Nipto ID to the private Auth email on the server, then delegates password verification to Supabase Auth. The recovery email is never returned by the lookup function.

## Current implementation status

The repository contains a Flutter Android app foundation and a live Supabase schema. Implemented app areas include Nipto ID registration/sign-in, profile editing and avatar uploads, photo posts, Nipto ID discovery and follow requests, direct/group conversation flows, text messages and basic media attachments, 24-hour statuses with owner-only viewer lists and Close Friends audience controls, Shorts upload/feed interactions, Home feed, in-app notifications, privacy controls, blocking/reporting, and private user feedback intake/history. Some flows still need deeper end-to-end, device and moderation validation.

The feedback subsystem is separate from abuse reports. Signed-in users can submit app-experience ratings, bug reports, feature ideas or support requests and view their own submission status. Feedback is protected by RLS and limited to five submissions per account per 24 hours. A trusted staff-role backend, moderation queues, audit logging and user response notifications are implemented. A role-gated staff console for feedback, reports and content review is implemented, including private signed media previews. Formatting, static analysis, unit/widget tests and Android debug APK CI have passed. Production staff-session acceptance testing remains an operational gate.

All 21 public application tables currently have Row Level Security enabled. Anonymous table privileges were revoked and client writes were narrowed. Authenticated application and moderation SECURITY DEFINER RPCs are explicitly granted to signed-in users and validate access server-side; private policy helpers and staff tables are not client-readable. The Supabase advisor continues to report these authenticated RPCs for manual review.

GitHub Actions generates the Android platform project, then runs Dart formatting, static analysis, tests and an Android debug APK build. The resulting `nipto-android-debug` APK is available as a workflow artifact. A passing CI run proves that the checked commit builds; it does not prove complete device-level or production readiness.
