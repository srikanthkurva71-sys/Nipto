# Nipto Social

**Nipto is an Android-first social communication app built around one Nipto ID.** It brings private messaging, status updates, social discovery, profiles and short-form video into one simple, fast experience.

This repository is the first implementation of Nipto Social. The former ride-hailing direction is out of scope.

## Product principles

- **One identity:** people register with a unique Nipto ID and sign in with that ID and their password.
- **Private by default where it matters:** private accounts, message membership checks, blocked-user enforcement and private media buckets.
- **Fast and calm:** four primary destinations, lightweight chat lists, paginated feeds and lazy video playback.
- **Creator-friendly:** simple status and short-video publishing, with content moderation before public distribution.
- **Android first:** Flutter + Dart. No web product is planned for v1.

## Main navigation

1. **Home** — paginated feed of approved posts, likes and comments from accounts visible to the signed-in user.
2. **Chats** — inbox, Nipto ID search, discovery, following, direct/group chats, 24-hour statuses and activity notifications.
3. **Shorts** — a vertical, swipe-first short-video feed with likes, comments and creator profiles.
4. **You** — personal profile, followers/following, photo posts, settings, privacy and security.

## Technology

| Layer | Choice |
|---|---|
| Android app | Flutter + Dart |
| Authentication | Nipto ID/password native forms with Supabase `custom:nipto` OIDC session broker (protocol flow verified; device validation gated) |
| Database | Supabase PostgreSQL |
| Authorization | PostgreSQL Row Level Security |
| Live messaging | Supabase Realtime |
| Media | Private Supabase Storage buckets with server-side magic-byte validation and staff review |
| Push | FCM HTTP v1 via a secret-protected dispatcher and a durable outbox; client-only Firebase identifiers |
| Privacy | Authenticated export/deletion requests with a secret-protected fulfillment worker |
| Server-side logic | Supabase Edge Functions |

## Local Android setup

Install Flutter stable, Java 17 and the Android SDK. From the repository root:

~~~powershell
.\\scripts\\bootstrap_nipto_windows.ps1
cd mobile/app
flutter run
~~~

The Flutter app includes the Nipto Supabase project URL and publishable key as client-safe defaults, so ordinary `flutter run`, `flutter run -d chrome`, and `flutter build apk` commands work without a configuration file. The Chrome host is for development preview only; Android remains the sole product target. Optional `--dart-define` values can override these defaults for another environment. A publishable key is intended for client apps; never embed a service-role key or backend secret.

The manifest setup script adds the `nipto://auth-callback` deep link required for Supabase OAuth. The Supabase Auth URL configuration must also allow that redirect URL.

## Run from VS Code

Open the repository root in VS Code, install the Flutter and Dart extensions, connect an Android phone or emulator, then select **Nipto (Android)** in Run and Debug and press F5. The launch configurations point to `mobile/app` and require no separate Supabase config file.

Nipto v1 is an Android app, not a web product. Use an Android emulator or physical Android device for plugin, media and calling validation.
