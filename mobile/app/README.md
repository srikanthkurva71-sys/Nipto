# Nipto Android application

This directory is the **Flutter package root**. Open the repository root in VS Code so the shared launch configuration and tasks work correctly.

## Folder layout

- `lib/main.dart`, `lib/nipto_app.dart` — app bootstrap and root widget.
- `lib/screens/` — current screen implementations.
- `lib/services/` — Supabase, secure storage, session and WebRTC services.
- `lib/theme/`, `lib/widgets/` — current shared UI layer.
- `lib/core/`, `lib/features/`, `lib/shared/` — reserved for the documented incremental feature-first migration; do not duplicate existing screens there.
- `test/` — Dart unit and widget tests.
- `assets/` — application-owned bundled assets.
- `config/dev.json` — client-safe development URL and publishable key only.
- `android/` — generated native Android host project; CI regenerates it.
- `pubspec.yaml` — the only source of Dart package dependencies.
- `pubspec.lock` — resolved versions generated by `flutter pub get`; commit it for reproducible app builds.
- `analysis_options.yaml` — Dart analyzer and lint configuration.

## Bootstrap on Windows

From the repository root in PowerShell:

```powershell
flutter doctor -v
flutter create --platforms=android --org com.nipto --project-name nipto mobile/app
python scripts/configure_android_manifest.py
Set-Location mobile/app
flutter pub get
dart format lib test
flutter analyze
flutter test
flutter run --dart-define-from-file=config/dev.json
```

Use Java 17 and Android SDK Platform 36. The Android app's minimum supported SDK is API 24. The generated app module must keep `minSdk = 24`.

## VS Code

Install the recommended Dart and Flutter extensions. Open the repository root (not only `mobile/app`), select **Nipto (Android)** in Run and Debug, connect an Android device or start an emulator, and press F5. Tasks are available for package resolution, analysis, tests and a debug APK build.

## Dependency policy

The current direct package dependencies are intentionally limited to Supabase, image selection, video playback, WebRTC and secure/local storage. Add a package only when a concrete implemented feature requires it, and declare it in `pubspec.yaml`; never rely on an undeclared transitive dependency.

Never place a Supabase service-role key, private signing key, TURN credential or other backend secret in this Flutter project. A publishable Supabase client key is not a service-role key, but backend authorization must still be enforced by RLS and server-side functions.
