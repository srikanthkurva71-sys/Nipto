# Nipto Android project structure

This document is the repository contract for local Windows/VS Code development. The Flutter package root is `mobile/app`; run every Flutter command from that directory unless the command explicitly says otherwise.

The native `android/` directory is generated from Flutter tooling and is not the source of truth for Dart dependencies. Do not manually copy Android Gradle caches, `.dart_tool/`, `build/`, or local SDK paths into Git.

## Feature-first destination for new code

New product work should be organized by feature instead of adding more unrelated files to the legacy `screens/` directory. Migrate existing files only when all imports, routes, tests and CI checks can be updated in the same change.

```text
lib/
├── main.dart
├── nipto_app.dart
├── core/
│   ├── config/                      # build-time configuration
│   ├── errors/                      # typed app errors
│   ├── security/                    # session and secure storage boundaries
│   └── utils/
├── features/
│   ├── auth/
│   │   ├── data/
│   │   ├── domain/
│   │   └── presentation/
│   ├── chat/
│   │   ├── data/
│   │   ├── domain/
│   │   └── presentation/
│   ├── calls/
│   ├── discovery/
│   ├── feed/
│   ├── notifications/
│   ├── profile/
│   ├── shorts/
│   └── status/
└── shared/
    ├── theme/
    └── widgets/
```

Feature boundaries:
- **presentation** owns screens, widgets and view state.
- **domain** owns feature entities, validation and use-case contracts.
- **data** owns Supabase queries, DTO mapping and repository implementations.
- Shared/core code must not import feature presentation code.
- UI widgets must not contain service-role credentials or bypass database authorization.

The current `screens/`, `services/`, `theme/` and `widgets/` directories remain in place while this migration is incremental. This avoids a risky mass move that would break imports and routes.

## Dependency policy

Only direct dependencies used by application source belong in `dependencies`. Current direct package imports are:

| Package | Responsibility |
|---|---|
| `supabase_flutter` | Supabase Auth, database, storage and realtime |
| `image_picker` | User-selected photo/video media |
| `video_player` | Feed, status and Shorts playback |
| `flutter_webrtc` | Audio/video call media |
| `flutter_secure_storage` | Secure session/credential storage |
| `shared_preferences` | Non-secret local PKCE/session metadata |

Flutter SDK libraries are provided by Flutter and must not be added as pub packages. `flutter_test` and `flutter_lints` are development dependencies. Do not add state-management, routing, JSON-generation or networking packages until an implemented requirement justifies them. Never store secrets in Dart defines, assets or source control; only the Supabase publishable key may be shipped to the client.

After changing `pubspec.yaml`, run `flutter pub get` and commit the generated `pubspec.lock` for this application.

## Windows setup and verification

Prerequisites: Git, Flutter stable, Dart supplied by Flutter, Java 17, Android SDK Platform 36, Android SDK Platform-Tools, Android SDK Build-Tools 36.0.0 and Android SDK Command-line Tools.

From PowerShell at the repository root:

```powershell
flutter doctor -v
flutter create --platforms=android --org com.nipto --project-name nipto mobile/app
python scripts/configure_android_manifest.py
Set-Location mobile/app
flutter pub get
dart format lib test
flutter analyze
flutter test
flutter run --dart-define-from-file=config/dev.json
```

For Android 7.0/API 24 minimum support, the generated Android app module must set `minSdk = 24`. CI also configures the Android host and WebRTC permissions. Review the generated manifest and Gradle files after regenerating the Android host.

## Physical-device checklist

1. Enable Android developer options and USB debugging on the test device.
2. Connect it by USB and confirm `flutter devices` lists it.
3. Open the repository root in VS Code; install the recommended Dart and Flutter extensions.
4. Select **Nipto (Android)** in Run and Debug, then press F5.
5. Validate runtime permissions for camera and microphone only when a call is started.
6. Test media upload, realtime chat, app lifecycle, call interruption and reconnect on a real device.
7. Never test with production credentials or real personal data.

A developer must copy/clone the repository into their own local folder and run the commands above. Remote repository edits do not modify a Windows folder automatically.
